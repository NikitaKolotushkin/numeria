# ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ: FRONTEND СЕРВИС («НУМЕРИЯ»)

* **Версия сервиса:** 0.1.6 (MVP in active dev)
* **Пилот:** продуктовый контур — `docs/spec-product.md`, серверный контракт — `docs/spec-backend.md`. Заявка дорожной карты описывает клиент как HTML/CSS/JS. Реализация клиента остаётся Vue 3, как в этом документе.
* **Архитектурный подход:** Feature-Based / Domain-Driven (FSD Lite) Single Page Application (SPA)
* **Стратегия разработки:** Frontend-First / Mock-Driven (изолированный UI с контрактами данных до появления бэкенда)
* **Основной стек:** Vue 3 (Composition API, `<script setup>`), Vite, Pinia, Vue Router, Axios
* **Шрифт интерфейса:** Geologica (Google Fonts) — на всём UI, включая инпуты и селекты
* **Целевое окружение:** Docker (Multi-stage build -> Nginx Alpine static server)

## 1. Назначение и архитектура ключевых экранов

Фронтенд-приложение образовательной экономической стратегии «Нумерия». Визуальная структура приложения базируется на следующих экранах:

1. **Главный экран / Хаб (`pages/LandingPage.vue`):**
   * **Состояние гостя (по умолчанию, без сессии):** промо-страница, партнерские блоки вузов (ГУУ, СПбГУ, СГТУ, «Твой Ход»), кнопки «Вход» / «Регистрация» справа сверху, «Начать игру» под логотипом.
   * **Состояние игрока (есть сессия в Pinia / `localStorage`):** справа сверху капсула «Выйти» (`authStore.logout` вызывает `POST /api/users/auth/logout`); справа по центру имя, статус и капитал из `GET /api/game/me/state`, иконки `hub/avatar.png` и `hub/coin.png`; строка «Топ-N» на этом экране не показывается; под логотипом кнопка «Играть!» (переход на `/game`). Протухший доступ клиент обновляет через `POST /api/users/auth/refresh`.

2. **Страница аутентификации и онбординга (`pages/AuthPage.vue`):**
   * Полноэкранный каркас мастера `AuthWizardLayout.vue` с навигационной шапкой (`BackPill`, капсула «Узнаем немного», слот `header-end`).
   * «Назад» — общий `shared/ui/BackPill.vue`: стрелка с чертой и `logo-mark.png`. Тот же компонент на `/game`.
   * `header-end` по умолчанию — капсула со стрелкой «Далее», той же длины, что «Назад». На экране кейса слот занят плашкой имени.
   * На шагах с фото справа («Познакомимся», «Защитимся», вход «Войдем») заголовок карточки выровнен по левому краю фото. «Персонализируем» и тест — заголовок по центру.
   * **Единый каркас шагов 1–4:** ширина и высота белой карточки фиксированы между этапами; внутренний padding одинаковый со всех сторон (`--auth-card-padding`). Масштаб с вьюпортом (`rem` / `vmin` / `vh` / `vw` / `clamp`, ландшафт).

   * **Толщины шрифта мастера:** заголовок шага 700, капсула шапки 500, поля / подписи / квиз / хобби 400.
   * **Модульный мастер регистрации (`AuthWizard.vue`):**
     * **Шаг 1 («Познакомимся» / `RegisterStepPersonal.vue`):** Сплит `form`. ФИО, вуз и направление — свободный ввод; курс — только цифра 1–6 + 3D-иллюстрация `step-personal.png`.
     * **Шаг 2 («Защитимся» / `RegisterStepSecurity.vue`):** Сплит `form`. Почта только `@guu.ru`, плейсхолдер «Почта @guu.ru», пароль, подтверждение и 3D-иллюстрация `step-security.png`. Согласий на этом шаге нет.
     * **Шаг 3 («Персонализируем» / `RegisterStepHobbies.vue`):** Сетка 3×2 интересов (Спорт, Кино, Музыка, Авто, Творчество, Книги) с PNG-постерами и SVG-галочкой выбора.
     * **Шаг 4 («Небольшой тест» / `RegisterStepQuiz.vue`):** Сплит `quiz`. 5 экономических вопросов, пагинация 1–5, варианты как радиокнопки без карточек. Неактивный кружок вопроса и невыбранный кружок ответа — `#E6EBED`, активный и выбранный — `#12202b`. Кружок ответа стоит по вертикали в середине всего текста варианта. Снизу капсулы «Назад» и «Вперед» размера шапочной стрелки, фон `#061e27`, стрелка белая. На первом вопросе «Назад» нет. На последнем «Вперед» завершает тест и открывает согласия, если отвечены все пять.
     * **Шаг 5 («Согласимся» / `RegisterStepConsents.vue`):** последний шаг мастера. Две галочки: обработка персональных данных и автоматизированная оценка ответов. «Далее» открывает экран готовности.

   * **Экран входа (`LoginWizard.vue`, `/auth?mode=login`):** тот же каркас мастера. Капсула «С возвращением», заголовок «Войдем». Сплит `form`: почта `@guu.ru` и пароль слева, компактная кнопка «Войти» по центру под полями, иллюстрация `step-security.png` справа. Кнопка и стрелка «Далее» вызывают `POST /api/users/auth/login` и редирект на `/`.
   * Сессия пишется в Pinia (`useAuthStore`) и `localStorage`: `access_token`, `refresh_token`, `user_data`. Регистрация с «Начнем» вызывает `POST /api/users/auth/register`.

3. **Игровой хаб (`pages/GamePage.vue`, маршрут `/game`):**

   * Слева капсула `BackPill`: «Назад» ведёт на `/`.
   * По центру карточка кейса в духе белой карточки мастера: тот же радиус, тень и цвет текста `#12202b`. Ширина `min(28rem, 34%)`, высота около четверти экрана. Заголовок (700): «{Здание}: {модуль}». Модуль — кейс этого здания из паспорта: лаборатория «Аналитика и статистика», завод «Производство», офис «Основы и введение», бухгалтерия «Бухгалтерский учет», маркетинг «Международные связи». При загрузке выбрана лаборатория. Клик по зданию меняет название и не сбрасывается кликом по пустой карте. Подзаголовок (400) со сессией — `currentTitle` здания из `game`. Название дисциплины и «Блок N» стоят на разных строках, по центру, без запятой, «Блок» с большой буквы. Босс остаётся одной строкой «Битва с боссом». Без сессии так же показывается первый блок модуля. Кнопка «Вперед!» у нижнего края, как «Войти»: `#061e27`, капсула. На сцене ниже 520px карточка ниже и уже, чтобы не закрывать офис.
   * «Вперед!» блюрит всю сцену, включая интерфейс, за 0,4 с (`blur(6px)`) и открывает `AuthWizardLayout` поверх карты. Капсула шапки — тот же заголовок, что на карточке. Заголовок белой карточки — подзаголовок кейса, чуть крупнее заголовка шага регистрации. Теория на всю ширину карточки. В тесте слева номера и текст вопроса, справа варианты. Серая панель `#E6EBED` есть только у босса: справа поле ответа или рецензия. Слева `BackPill` закрывает окно и снимает блюр. Справа плашка имени, не стрелка «Далее». В этих колонках стоит раннер из `frontend/spec-case-window.md`.
   * Справа две капсулы в стиле `BackPill`, одной ширины по более длинной: имя и капитал. Без сессии — «Линад» и 1600. Со сессией — `firstName` и капитал из `GET /api/game/me/state`.
   * Пять зданий, слева направо: лаборатория, завод, офис, бухгалтерия, маркетинг. Верхний ряд — лаборатория, офис, маркетинг; нижний — завод и бухгалтерия. Клик считается по непрозрачным пикселям спрайта.
   * Без сессии у всех зданий уровень 1 и спрайт `level-1`. Со сессией уровень и спрайт берутся из `game`. Расчёт размера по уровню сохранён (`placeBuilding`, `LEVEL_GROWTH`, `LEVEL_MAX_SCALE`).
   * Все уровни — квадрат 1984×1984. Рисунок 1-го уровня занимает середину кадра, старшие заполняют кадр сильнее. На экране размер растёт вместе с этим, но приглушённо: коэффициент `LEVEL_GROWTH = 0.34`, потолок `LEVEL_MAX_SCALE = 1.5` относительно 1-го уровня. Основание и центр видимого здания остаются на плитке. Подпись стоит у основания текущего спрайта.
   * Клик по зданию сразу открывает плашку угла у курсора. Прямой угол только у курсора, остальные скруглены. Левая половина видимого здания открывает плашку влево, правая — вправо; по вертикали по умолчанию вниз. Если плашка не помещается в сцену, эта ось переворачивается, и прямой становится угол, который остался у курсора.
   * Плашка `#002126`. Заголовок обычного начертания: «{Здание} (ур. N)». Дальше три строки: освоение модуля, текущая тема, условие апгрейда. Со сессией это `mastery`, `currentTitle` и `nextCondition` из `game`. Тема в плашке — одна строка «{дисциплина}, Блок N», без выравнивания по центру. Без сессии освоение `0 / всего шагов` этого модуля, тема — первый блок в том же виде, условие — «Пройти теорию и тест». Подписи строк жирные.
   * Пока плашка здания открыта, карта размывается за 0,4 с (`blur(6px)`). Резкими остаются плашка, здание с подписью и верхний интерфейс: «Назад», карточка кейса, имя и капитал. Интерфейс остаётся над слоем блюра, пока размытие полностью не спадёт. Окно кейса блюрит и карту, и этот интерфейс. Сама плашка появляется и исчезает сразу. Смена здания: блюр сначала полностью спадает, затем новая плашка появляется и блюр набирается снова. Повторный клик по тому же зданию блюр не перезапускает. Клик по пустой карте закрывает плашку, выбранное здание в заголовке не меняет.
   * `useGameStore` читает капитал, опыт и уровни. Отдельной `ResourceBar` и модалки улучшения нет: уровень меняет только прогресс в `game`. Плашка — информационная карточка, не окно апгрейда.

4. **Окно кейса на карте** (`frontend/spec-case-window.md`):
   * Раннер живёт в окне «Вперед!», отдельная `pages/CaseRunnerPage.vue` и маршрут `/study` не заводятся.
   * Со сессией «Вперед!» читает трек `study` и открытый блок. Теория стоит над тестом. Первое открытие пустого шага ждёт текст от `ai`. Если сервис не ответил, в колонке текст `504`. Сдача пишет попытку и заново читает `game`. Без сессии остаётся мок из трёх вопросов.
   * Если текущий шаг — босс, справа поле «Ваш ответ». После отправки его сменяет карточка рецензии: балл, вердикт, разбор и зоны роста. Правила прогресса, порог 70 и форма оценки — в `docs/spec-product.md`.
   * Кризис с таймером остаётся отдельным окном, не второй режим этих двух колонок.

## 3. Что уже реализовано (Status: Done)

1. **Базовый каркас и инфраструктура:**
   * Vite + Vue 3 (Composition API), алиас `@` -> `src`.
   * Шрифт **Geologica**, тёмная тема, CSS-токены.
   * Ландшафтная адаптивность: `html { font-size: clamp(16px, 1.8vmin, 20px) }` при `orientation: landscape`; размеры UI в `rem` / `clamp` / `vh` / `vw`.

   * Выделение текста отключено глобально (`user-select: none` на `*` в `main.css`).
   * Docker (Node 20 -> Nginx Alpine), SPA `try_files`.

2. **Маршрутизация:**
   * `/`, `/auth`, `/game`; обновление `document.title`.

3. **Онбординг и сессия:**
   * `useAuthStore` пишет сессию из `POST /api/users/auth/login` и `POST /api/users/auth/register`.
   * Шаги 1–5 в общем каркасе + welcome-экран после согласий. Две галочки стоят на последнем шаге.
   * Экран входа в том же каркасе (`/auth?mode=login`).
   * Тост ошибок поверх UI (3 с).
   * 3D-постеры шагов «Познакомимся», «Защитимся» и сетки хобби.

4. **Главный экран:**
   * Гость — промо, партнёры, вход/регистрация.
   * Игрок — панель `hub/` (аватар, монета, кубок), «Играть!», «Выйти».

## 5. Регламенты и стандарты разработки фронтенда

1. **Компонентный стиль:**
   * Использовать **исключительно** Composition API (`<script setup>`).
   * Стили компонентов строго изолированы (`<style scoped>`). Декоративных инлайн-стилей нет. Координаты плашки и коробки здания задаются CSS-переменными из шаблона.
   * DRY: общие паттерны разметки выносятся в `modules/auth/components/common/`.

2. **Графика и дизайн-система (Zero-Emoji Policy):**
   * **Категорически запрещено** использовать Unicode-эмодзи в UI.
   * Иконки навигации мастера и галочка хобби — **SVG**. Иконки хаба игрока — **PNG** в `src/assets/images/hub/` (`avatar.png`, `coin.png`, `trophy.png`).
   * Капсульные инпуты и кнопки: `border-radius: 9999px`.
   * Без hover-подъёма (`translateY`) и без появления обводки у кнопок.
   * 3D-постеры онбординга лежат в `src/assets/images/auth/` с фиксированными именами (`logo-mark.png`, `step-personal.png`, `step-security.png`, `hobby-*.png`).
   * Здания игрового хаба — PNG с прозрачным фоном в `src/assets/images/game/buildings/`. Папки слева направо: `01-laboratory`, `02-factory`, `03-office`, `04-accounting`, `05-marketing`. В каждой ровно `level-1.png` … `level-5.png`, холст 1984×1984. `level-1` — первое построенное здание, `level-5` — максимум. Пустая плитка отдельным файлом не задаётся: это фон `map.png`.
   * Выделение текста во всём приложении запрещено.

3. **Адаптивность:**
   * Нормирован **ландшафт** (`orientation: landscape`).
   * Каркас мастера (шапка + карточка) одинаков на шагах 1–4; масштабируется относительными единицами, а не отдельными брейкпоинтами на каждый шаг. Ниже 520px по высоте поля регистрации и входа уплотняются и остаются внутри карточки.
   * Карточка кейса на сцене ниже 520px становится ниже и уже, чтобы не накрывать офис.
   * Портрет закрыт заглушкой «Переверните экран». Портретная вёрстка экранов — отдельная задача.

4. **Управление состоянием (Pinia):**
   * Бизнес-логика сессии, баланса и ресурсов — только в `modules/<module_name>/store/`.

5. **Mock-First регламент сетевого слоя:**
   * Все запросы в `modules/<module_name>/api/`.
   * До бэкенда — `Promise` с задержкой 200–400 мс.
   * Моковые данные не хранить внутри `.vue`.

6. **Импорты путей:**
   * Только алиас `@/`. Относительные пути `../../` запрещены. Исключение: `import.meta.glob` спрайтов зданий в `GamePage.vue` — Vite резолвит такой glob от файла, не через алиас.

7. **Пилот:**
   * Учебный состав, формула уровня, кризисы, оценка босса и карточка профиля берутся из `docs/spec-product.md`.
   * Почта на входе и регистрации принимается только с доменом `@guu.ru`. Вуз хранится отдельным полем. Сервис `users` это ограничение пока не повторяет.
   * Экран куратора и администратора — отдельный маршрут, не сцена карты. Его API описан в `docs/spec-backend.md`.
