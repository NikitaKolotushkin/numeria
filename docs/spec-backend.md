# Техническая спецификация: backend пилота «Нумерия»

Контракт продукта: `docs/spec-product.md`. Таблицы: `docs/spec-backend-schema.md`. Тела запросов и ответов: `docs/spec-backend-api.md`. Этот документ описывает сервисы, которые уже заведены в `docker-compose.yml` и проксируются nginx. Новые сервисы для пилота не добавляются.

Стек пилота: Python, FastAPI, PostgreSQL 15, SQLAlchemy, Alembic, Pytest. Redis и Kafka входят в целевой контур дорожной карты. В текущем compose их нет: пока шина не поднята, сервисы вызывают друг друга по HTTP внутри `numeria_network`. Контракты ниже от этого не меняются. Когда Redis и Kafka появятся, фоновые отправки писем и генерация кризисов уезжают туда, наружу остаются те же маршруты.

Браузер ходит только в nginx: `/api/users/`, `/api/study/`, `/api/game/`, `/api/crisis/`, `/api/career/`, `/api/ai/`, `/api/notifications/`. Префикс сервиса nginx срезает. Модель GigaChat с браузера не вызывается.

Домен пилота: `numeria-game.ru`.

Собраны `users`, `study`, `game` и `ai`. У `crisis-engine`, `career` и `notifications` в репозитории пустой Dockerfile, поэтому полный `docker compose up` не стартует. Поднимается то, что уже собирается:

```bash
COMPOSE_BAKE=false docker compose up -d --build postgres users study game ai frontend nginx
```

Nginx для API снимает префикс сервиса и передаёт остаток пути. `POST /api/users/auth/register` приходит в `users` как `POST /auth/register`. В `proxy_pass` с переменной путь задаётся явно, иначе запрос уходит на `/`.

`POSTGRES_MULTIPLE_DATABASES` создаёт семь баз только при первом создании тома Postgres. Если том на сервере уже был до этой настройки, базы не появятся сами, и миграция `users` упадёт. На сервере `JWT_SECRET` задаётся в `.env`. Значение по умолчанию в compose — только для локальной разработки.

Клиент со сессией вызывает `users`, `study` и `game`. Локальный `vite` проксирует `/api` на `127.0.0.1`, то есть на nginx из compose. Без сессии карта остаётся гостевой и в эти сервисы не ходит.

---

## 1. Данные

Один экземпляр Postgres, отдельная база на сервис через `POSTGRES_MULTIPLE_DATABASES`:

`numeria_users`, `numeria_study`, `numeria_game`, `numeria_crisis`, `numeria_career`, `numeria_ai`, `numeria_notifications`.

Чужие таблицы не читаются. Чужой прогресс приходит событием или внутренним HTTP-запросом.

Идентификаторы зданий, модулей и дисциплин — строки из продуктовой спеки (`office`, `factory`, `laboratory`, `marketing`, `accounting` и id дисциплин). Уровень здания считает только `game`.

---

## 2. Пользователи (`users`)

Аккаунт: почта, хэш пароля, имя, фамилия, вуз, направление, курс, хобби, роль (`student`, `curator`, `admin`), три времени согласия (персональные данные, соглашение, ИИ-оценка). Профиль сеттинга хранит `ai`, не `users`.

Публичные маршруты:

- `POST /auth/register` — создаёт студента. Без трёх согласий отвечает 422. Пароль в ответе не возвращается.
- `POST /auth/login` — выдаёт `accessToken`, `refreshToken` и пользователя. Клиент уже кладёт токен доступа в `localStorage` под ключом `access_token` и шлёт `Authorization: Bearer`.
- `POST /auth/refresh` — меняет пару токенов и отзывает старый refresh.
- `POST /auth/logout` — отзывает свой refresh и гасит `jti` доступа.
- `GET /me` — профиль текущей сессии.
- `PATCH /me` — имя, вуз, направление, курс, хобби. Почта и роль этим маршрутом не меняются.

После записи аккаунта `users` один раз вызывает `game` (создать игрока), `ai` (профиль сеттинга) и `notifications` (письмо регистрации). Сбой любого из трёх, пустой адрес сервиса или таймаут не откатывает аккаунт и не меняет ответ 201. Ограничения домена `@guu.ru` на этом слое нет.

Переменные сервиса: `DATABASE_URL`, `JWT_SECRET`, `SERVICE_TOKEN`, `GAME_BASE_URL`, `AI_BASE_URL`, `NOTIFICATIONS_BASE_URL`. Подпись токена — общий секрет `JWT_SECRET`, алгоритм HS256. Отдельный приватный ключ не используется.

Куратор и администратор проходят тем же входом. Доступ к чужому прогрессу и правке контента проверяет роль на каждом закрытом маршруте.

## 3. Учёба (`study`)

Хранит модули, дисциплины, блоки, теорию, вопросы, боссов, попытки и пересдачи. Правильный индекс вопроса и ключ кризиса наружу студенту не отдаются.

Студенческие маршруты:

- `GET /tracks/{buildingId}` — модуль здания, список шагов, какой шаг текущий, какие блоки на пересдаче, открыт ли босс.
- `GET /blocks/{blockId}` — теория и вопросы без верного индекса.
- `POST /blocks/{blockId}/attempts` — ответы теста. Ответ: доля верных, балл 0–100, сдан ли шаг. Порог по умолчанию 70 и читается из конфига.
- `GET /bosses/{bossId}` — текст кейса. Открыт только когда все блоки модуля сданы и нет пересдачи.
- `POST /bosses/{bossId}/attempts` — текст ответа. `study` отдаёт ответ и теорию модуля в `ai`, сохраняет балл, вердикт, разбор и зоны роста.
- `GET /me/progress` — сданные шаги по зданиям.

Запись попытки, которая сдала шаг или открыла пересдачу, сообщает `game`. Пока нет шины, это `POST` во внутренний маршрут `game`.

Слоты модулей, дисциплин и блоков сидируются пустыми. Текст блока и босса не заливается заранее: `GET` шага, у которого ещё нет среза этого игрока, один раз зовёт `ai` и сохраняет срез. Дальше чтение идёт из среза.

Админские маршруты, роль `curator` или `admin`, в пилоте только читают попытки студентов. Отдельной выгрузки банка нет. Удалить вопрос из уже выданного среза нельзя: по нему уже может быть ответ.

---

## 4. Игра (`game`)

Хранит капитал, опыт и уровень пяти зданий. Стартовые значения: капитал 0, опыт 0, все здания уровня 1. Клиентский запас «1600» и имя «Линад» — экран без сессии, не запись в базе.

При создании игрока строка `players` фиксируется до строк `buildings`: внешний ключ Postgres иначе отвергает здания.

Внутренний маршрут `POST /internal/progress` принимает факт из `study` или `crisis`:

- `block_passed` — начислить награду теста, пересчитать уровень;
- `boss_passed` — начислить награду босса, пересчитать уровень;
- `retake_required` — снять шаг из сданных, пересчитать уровень, капитал не увеличивать;
- `crisis_failed` — вычесть штраф, пол нуля.

Формула уровня:

```text
level = min(5, 1 + floor(4 * passed_steps / total_steps))
```

Если шагов ещё нет в `study`, `total_steps` этого здания берётся из привязки `content_binding.v1`. Числа наград и штрафа — конфиг баланса, не константы в коде обработчика.

Студенческие маршруты:

- `GET /me/state` — капитал, опыт, место в рейтинге, пять зданий с уровнем и подписями плашки (освоение, текущий шаг, условие следующего шага). Подписи `game` собирает из прогресса `study`.
- `GET /leaderboard` — порядок по монетам (капиталу), для строки «Топ-N». Опыт на место не влияет.

Энергии в состоянии нет.

---

## 5. Кризисы (`crisis-engine`)

Активное событие одно на игрока. Новое не выдаётся, пока предыдущее не закрыто или пока у игрока нет ни одного сданного блока.

Генерация: сервис выбирает сданный блок без пересдачи, просит у `ai` черновик и сохраняет событие с дедлайном. Длительность таймера — конфиг, стартовое значение 90 секунд.

Маршруты:

- `GET /me/active` — текст, варианты, момент окончания. Верный вариант в ответ не входит.
- `POST /events/{eventId}/answer` — выбранный вариант. После дедлайна тот же эффект, что у неверного ответа, даже если тело запроса пришло позже.
- Верный ответ закрывает событие.
- Неверный ответ зовёт `game` (`crisis_failed`) и `study` (пересдача связанного блока).

Появление события уходит в `notifications`.

---

## 6. ИИ (`ai`)

Единственное место, где хранится ключ GigaChat. В лог не пишутся пароль, токен сессии, Authorization key и полный текст согласия. База `numeria_ai` таблиц не имеет: ниша и тон лежат в памяти процесса, access token тоже.

Ключ читается из `GIGACHAT_CREDENTIALS` или, если его нет, из `GIGACHAT_API_KEY`. Это Authorization key кабинета. Сервис сам вызывает `POST /api/v2/oauth` и кэширует access token до момента за минуту до `expires_at`. При ответе 401 токен запрашивается ещё раз. Сертификат хоста Сбера в этом контуре не проверяется: без этого обмен не устанавливается.

Вызов модели ограничен 40 секундами. `study` ждёт ответ `ai` до 50 секунд.

Внутренние маршруты:

- `POST /internal/personalize` — хобби и ответы онбординга. Сохраняет нишу и тон локальной таблицей. Учебные факты не генерирует и модель не вызывает.
- `POST /internal/material` — первое открытие блока или босса. Модель пишет теорию и вопросы либо текст кейса. Негодный ответ заменяется заготовкой из `services/ai/app/corpus.py`.
- `POST /internal/review` — текст босса, теория модуля, ответ студента. Возвращает `score` 0–100, `verdict` (`accepted` или `retry`), `reviewText`, `growthZones`. Вердикт считается от порога, модель сама порог не объявляет. Если модель не ответила, балл считается по опорам заготовленного кейса.
- `POST /internal/crisis-draft` — шаблон микро-кейса по нише и началу теории. Модель не вызывается. Ключ верного варианта остаётся у будущего `crisis-engine`.

Промпт оценки требует разбор логики и прикладной ценности и запрещает выдумывать цифры, которых нет в условии и в теории блока. Поиска по учебной базе нет.

Журнал запросов в таблице ещё не пишется. Текст ответа студента хранится в `study.boss_attempts`.

---

## 7. Карьера (`career`)

Не ходит в GigaChat. Собирает карточку чтения.

- `GET /me/card` — полная карточка владельца.
- `GET /cards/{userId}` — публичный вид: имя, вуз, капитал, опыт, уровни зданий, сданные боссы, дисциплины. Почты и ответов нет.

Данные каждый раз читаются из `users`, `study` и `game`. Своей копии прогресса сервис не ведёт, чтобы карточка не расходилась с картой.

---

## 8. Уведомления (`notifications`)

Письма по SMTP: регистрация, открытый кризис, дайджест прогресса. Дайджест собирается не чаще одного раза в сутки на игрока и только если за сутки был сданный шаг или кризис.

Сервис не показывает учебное окно и не хранит прогресс. Ошибка SMTP не откатывает регистрацию и не отменяет кризис: письмо повторяется, игровой факт уже записан у владельца.

Тосты интерфейса остаются на клиенте. Этот сервис их не заменяет.

---

## 9. Нефункциональные условия

- Доступ к учебным и игровым маршрутам только с действительным токеном. Чужой `userId` в теле запроса игнорируется, игрок берётся из токена.
- `curator` не меняет роли и не читает пароли. `admin` меняет роли.
- Простой пилота укладывается в 7 часов 12 минут за месяц.
- Самый тяжёлый визуальный файл клиента отдаётся так, чтобы уложиться в 3,2 секунды на целевом канале пилота. Это условие nginx и статики, не Python.
- Секреты модели, SMTP и базы приходят из окружения, не из репозитория.

---

## 10. Вне пилота

Мультиплеер, командные корпорации, рекомендации стажировок, витрина кандидатов для компаний, отдельный модуль под LMS вуза, вторая модель GigaChat 2 Lite. Поля под них в таблицах не заводятся заранее.
